# Workflow Schema

## Top-Level Structure

Each workflow has these main fields:

- `id`
- `name`
- `description`
- `requiresConfirmation`
- `inputs`
- `steps`

## Example

```json
{
  "id": "extract-local-package",
  "name": "Extract Local Package",
  "description": "Extracts a locally downloaded zip package.",
  "requiresConfirmation": false,
  "inputs": [
    {
      "name": "version",
      "label": "Version",
      "type": "text",
      "defaultValue": "0.5.29"
    }
  ],
  "steps": [
    {
      "type": "extractArchive",
      "name": "Extract local zip",
      "archivePath": "C:\\Downloads\\package-{{version}}.zip",
      "destinationPath": "C:\\Downloads\\package-{{version}}",
      "cleanDestination": true
    }
  ]
}
```

## Top-Level Fields

### `id`

String.

Should be stable and unique across all workflow files.

Recommendation:

- use a readable ID like `download-edge-extension`
- do not rely on autogenerated fallback IDs

### `name`

String.

Used in the dashboard UI.

### `description`

String.

Shown in the workflow widget to explain the purpose of the workflow.

### `requiresConfirmation`

Boolean.

If `true`, the dashboard asks for confirmation before starting execution.

### `inputs`

Array of workflow input definitions.

Each input supports:

- `name`
- `label`
- `type`
- `defaultValue`

Current supported input type:

- `text`

### `steps`

Ordered array of step objects.

Steps run in sequence.

If one step fails, the workflow fails.

## Input Schema

Example:

```json
{
  "name": "version",
  "label": "Version",
  "type": "text",
  "defaultValue": "1.0.0"
}
```

### `name`

Internal placeholder name.

Used as:

- `{{version}}`

### `label`

Display name shown in the input modal.

### `type`

Currently only:

- `text`

### `defaultValue`

Pre-filled value in the input modal.

## Placeholders

Any string step field may include placeholders using this format:

- `{{inputName}}`

Example:

```json
{
  "targetPath": "C:\\Temp\\package-{{version}}.zip"
}
```

## Step Execution Model

Each step:

- is normalized by the backend
- resolves placeholders before execution
- logs status and errors
- can fail the workflow
